# ADR-0001：数据与展示分离

- 状态：已采纳（M0）
- 日期：2026-08

## 背景

生态里两种既有做法：WhaleHub（网站 + 自维护 registry）、dsh-find-plugins（技能，直接抓 topic）。前者把抓取逻辑绑死在网站里，后者每次调用都现抓、无缓存无排行。

## 决策

本项目把「数据管道」作为独立资产：`scripts/` + `data/` 是本仓库的核心，DSH 插件、静态站、外部消费者都只读 `data/*.json`，不各自抓取。

## 理由

1. 抓取逻辑只写一次，任何新消费端零成本接入
2. 数据变更走 git 历史 = 审计日志 + 可回滚
3. 其他项目（如别的插件作者）可以直接复用我们的 registry.json，生态价值外溢
4. 展示层（插件/网站）可独立迭代，不影响数据可信度

## 代价

- 数据与消费端分属不同仓库时，消费端要处理「数据仓库更新延迟」
- 单仓库内则无此问题（data/ 与 scripts/ 同仓提交）
